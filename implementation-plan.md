## High Priority

### 1. `pnpm lint` is broken — project hooks fail ESLint

- **Category**: Code Quality / Tooling
- **File(s)**: `.claude/scripts/hooks/build-verify.js:11`, `.claude/scripts/hooks/eslint-on-edit.js:10`, `.claude/scripts/hooks/eslint-on-edit.js:11`, `eslint.config.mjs:10-15`
- **Issue**: ESLint flags 3 errors under `@typescript-eslint/no-require-imports` because the new Claude project hook scripts use CommonJS `require()`. ESLint's `globalIgnores` in `eslint.config.mjs` does not include `.claude/**`, so these tooling files are linted as if they were app code. `pnpm lint` exits non-zero, which will break CI as soon as it lands and currently breaks the project hook itself (`eslint-on-edit.js` will surface its own lint errors back to Claude after each edit).
- **Fix**: Add `.claude/**` to the `globalIgnores([...])` array in `eslint.config.mjs`. The hook scripts are tooling, not application code, and live outside `src/`. After the change, `pnpm lint` should exit 0 again. Verify with `pnpm lint` from the project root.
- **Complexity**: Low (< 5 min)

### 2. `src/proxy.ts` declares an admin matcher but performs no gate

- **File(s)**: `src/proxy.ts:1-9`
- **Category**: Security / Incomplete Feature
- **Issue**: The proxy (Next.js 16's renamed middleware) sets `matcher: ['/admin/:path*']` but the function body is `return NextResponse.next()` — every request passes through unmodified. The design spec § 9.5 mandates that admin middleware check an `x-admin-secret` header against `ADMIN_SECRET`, and `env.ts:10` already requires `ADMIN_SECRET`. This is benign today because `/admin/page.tsx:5` is a static "Stub for the M1 Notion sync panel" with no sensitive content — but the moment Task 18 ("Admin gate middleware") + Task 19 (sync API route) land in M1, an attacker can hit the sync endpoint without credentials. The file gives a false signal that the gate exists.
- **Fix**: Either (a) implement the real admin gate now per plan Task 18 (`docs/superpowers/plans/2026-04-14-frame-bucket-m0-m2.md:1898`) — read `x-admin-secret` from headers, compare against `env.ADMIN_SECRET`, return 401 on mismatch, restrict to `/api/admin/*` and `/admin` routes; or (b) add a clear `// TODO(M1, Task 18): real admin gate` comment and tighten the matcher to `/api/admin/:path*` so the no-op middleware doesn't even sit in front of the static `/admin` page. (a) is the durable fix.
- **Complexity**: Medium (1-2 hrs for the real gate including a vitest unit test)

### 3. No CI workflow — quality gates only run locally

- **File(s)**: `.github/workflows/` (does not exist)

- **Issue**: There is no CI configuration. `pnpm lint`, `pnpm test`, `pnpm typecheck`, and `pnpm build` only run when the developer remembers to. Also closes a 3-pt finding from the harness audit.

Use `actions/setup-node@v4` with Node 20 (matches `engines` in `package.json:5-7`) and `pnpm/action-setup@v4` pinned to pnpm 10.32.1 (matches `packageManager` in `package.json:8`). ### 4. Vitest coverage config points at a directory that doesn't exist

- **File(s)**: `vitest.config.ts:11-13`
- **Category**: Code Quality / Configuration
- **Issue**: `coverage.include` is `['src/lib/**/*.ts']` but `src/lib/` does not exist in the current scaffold. Running `pnpm test --coverage` today would report 0% coverage with no files matched, which is misleading. Plan Task 9 (`slugify` utility, line 707) will create `src/lib/`, after which the config will start working. But until M1 lands, coverage reporting is silently broken.

(b) Broaden now: change `include` to `['src/**/*.{ts,tsx}']` with `exclude: ['src/**/__tests__/**', 'src/app/**', 'src/proxy.ts', 'src/env.ts']` so coverage measures everything testable today. ### 6. No central logger module — every M2+ feature will need one

- **File(s)**: `src/` (no `src/lib/logger.ts` or equivalent)
- **Category**: Incomplete Feature / Future Infra
- **Issue**: The spec calls for cost-per-request logging (§ 7.4), cache hit/miss logging (§ 7.5, R14), audit log on Notion sync (§ 9.1), and `console.log` is rule-banned for production code (`eslint.config.mjs:21` warns; the user's TS coding-style.md forbids it outright). M0 doesn't ship a logger; the moment M1 Task 17 (Sync orchestrator) or M2 Task 30 (Anthropic client wrapper) lands, every contributor will reach for `console.log` and run into the lint warning. Picking a logger now (and standardizing the call shape) prevents that thrash.
- **Fix**: Add `src/lib/logger.ts` exporting `logger.info/warn/error(message, meta?)`. Two reasonable options: (a) thin wrapper over `console.warn/error` with a stable shape — zero deps, satisfies the existing ESLint allow-list — and a `// TODO(M2): swap for pino when we add structured ingestion`. (b) Pick `pino` now and standardize on it. (a) keeps M0 light; (b) prevents a future migration. Recommend (a) for now since the project is pre-Notion-sync.
- **Complexity**: Low (~45 min)

## Low Priority

### 7. `ANTHROPIC_API_KEY` is validated only as `string().min(1)`

- **File(s)**: `src/env.ts:4`
- **Category**: Hardcoded Value / Input Validation
- **Issue**: A typo'd or pasted Notion key would currently pass env validation. Anthropic keys have a stable `sk-ant-` prefix; same idea for Notion keys (`secret_` or `ntn_`). Catching the wrong-key-in-the-wrong-slot mistake at boot is cheaper than a confusing runtime 401 mid-stream from the Anthropic SDK.
- **Fix**: Tighten to `z.string().regex(/^sk-ant-/, 'ANTHROPIC_API_KEY must start with sk-ant-')` and `z.string().regex(/^(secret_|ntn_)/, 'NOTION_API_KEY must start with secret_ or ntn_')`. Update the corresponding test in `src/__tests__/env.test.ts` to seed valid prefixes. Verify Anthropic and Notion key formats from their dashboards before locking the regex.
- **Complexity**: Low (15 min)

### 8. `BLOB_READ_WRITE_TOKEN` is optional everywhere — but the spec requires it on Vercel

- **File(s)**: `src/env.ts:11`, `src/env.ts:14`
- **Category**: Input Validation / Future Bug
- **Issue**: Spec § 9.3 chooses `BlobStore` when `process.env.VERCEL` is set, which means the blob token becomes mandatory only in that scenario. Today the schema treats both `BLOB_READ_WRITE_TOKEN` and `VERCEL` as independent optionals, so a Vercel deploy without the blob token would currently boot fine and only fail when sync is attempted. Defer-able until M1+ but cheap to fix proactively.
- **Fix**: Add a `.refine()` on the Zod schema: if `VERCEL === '1'` (or any truthy value), `BLOB_READ_WRITE_TOKEN` must be present. Add a unit test in `src/__tests__/env.test.ts` covering both branches.
- **Complexity**: Low (20 min)

### 9. `next.config.ts` is empty placeholder — no production CSP / headers configured

- **File(s)**: `next.config.ts:1-7`
- **Category**: Security / Future Infra
- **Issue**: The user's web/security.md mandates a production CSP with nonce-based script-src plus HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, and Permissions-Policy headers. None of those are configured. M0 generates static stub pages so the gap is academic, but M3+ ships generated HTML in iframes (sandboxed per spec § 8.6) and M5 introduces the real preview surface — that's where headers genuinely matter. Worth landing the static headers now and revisiting nonce-based CSP closer to deploy.
- **Fix**: In `next.config.ts`, add `async headers()` returning the stable headers (HSTS, nosniff, frame-deny, strict-origin-when-cross-origin, restrictive Permissions-Policy). Defer CSP until M5 because nonce wiring requires per-request work. Reference the spec's web/security.md for the exact header values and don't cargo-cult the example block unmodified.
- **Complexity**: Low (~30 min for static headers, larger work for proper CSP later)
